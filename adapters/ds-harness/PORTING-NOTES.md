## 二、脚本层移植发现

| # | 发现 | 影响/处置 |
|---|------|-----------|
| 1 | 抽样器不先验 INDEX/台账存在：有卡但无台账 → FileNotFoundError traceback，非友好报错 | 前置校验，读台账前 `os.path.exists` 给「错误：未找到 _氨基酸库\闪电台账.md」类提示（R1） |
| 1b | 状态页生成器同样无存在性预检（缺 INDEX/台账 → 裸 traceback） | 与 1 同类，并入 R1：两个生成器入口统一预检 + 友好报错 |
| 2 | 抽样器根本不读 INDEX.md：无 INDEX 目录照常跑通 | 契约上 INDEX 是 skill 入口但脚本依赖只覆盖卡文件与台账；加 `--strict` 可选一致性校验 |
| 3 | 空目录明确报错「未发现任何 <文件夹>/_氨基酸.md」、退出码 1、零副作用 | 行为正确，保留 |
| 4 | 台账数据行 <10 → 退化均匀抽样（MIN_ROWS=10）；权重表仍打印并标注「退化模式下不参与抽样」 | 参数化（R2） |
| 5 | `## 未解问题` 节存在但 0 条目 → 提示级（×1.0）；节缺失 → 告警级（×1.0） | 语义已明确，保持 |
| 6 | 卡级裁定句式〔卡级裁定：卡全名=档；…〕按卡取赫布；无句式行回退行级「强认可」子串；「是（仅X）」「某某卡无有效碰撞（静默）」为可解析规范句式 | 正则常量随脚本搬运 + 单测（R3） |
| 7 | 蛋白质：基线＝成员最终权重实时最大值，再叠乘自身 h/z/d；同族去重＝蛋白质×成员不同出（后到让位），成员相互不受限 | 逻辑正确；基线随成员衰减变化 |
| 8 | 状态页生成器注入 `__STAMP__` 时间戳（now）→ 同分钟两次运行一致、跨分钟不一致 | 非严格确定性；加 `--stamp 固定值` 参数化（R4） |
| 9 | M5 结算脚本实跑验证：`subprocess.run` 复用抽样器解析段；**9009 失败模式**——硬编码 `python3` 裸 spawn 命中 WindowsApps 存根 → returncode 9009、stdout/stderr 全空 → 抽样器段解析 IndexError → 误导性报错 | 解释器 `sys.executable` 优先 + py→python→python3 探测 + spawn 失败/9009/空输出明确报错；`--sampler` 显式路径；shim 转发（只读执行真实抽样器、stdio 继承）在合成夹具实证 EXIT=0 且输出与人工预推一致（关闭 2/强认可 0/67-7-60） |
| 10 | 全库 .py 实为 7 个：4 个机制脚本 + 3 个属其他技能自带 | 移植范围＝4 个机制脚本 |
| 11 | 潮汐周报生成器：字段行须 `- 【label】text`，对账按「html 去标签文本 ⊇ md 每非空行」，缺失退出码 3（文件仍写出）；全静态零 JS | 保持对账逻辑（质量闸门） |
| 12 | 中文显示宽度对齐：`unicodedata.east_asian_width` 计算 CJK 宽字符宽度 | Windows 控制台同样适用，无需改 |
| 13 | 编码：抽样器 `sys.stdout.reconfigure(encoding="utf-8")`；读文件 utf-8-sig（抽样器）vs utf-8（状态页/潮汐）不一致 | 统一读 `utf-8-sig`；断言以重定向文件为准（cmd 重定向保原始字节；PS 7 默认 UTF-8 无 BOM） |
| 13b | 潮汐周报生成器缺 stdout reconfigure → Windows 重定向落本地编码（实测 GBK） | 补 reconfigure（R6） |
| 13c | 抽样器只 reconfigure stdout、未动 stderr → traceback 中文以本地编码落盘 | 一并 reconfigure stderr |

## 三、契约基线

| # | 基线事实 | 说明 |
|---|----------|------|
| 16 | **蛋白质不进 INDEX**：INDEX 仅 A 序列登记，P 号只写进蛋白质卡自身 `## 编号` 段；抽样池仍含蛋白质（抽样器按 `_氨基酸库/蛋白质：*.md` glob 发现，与 INDEX 无关）；状态页「氨基酸」KPI＝INDEX 数据行数 | 样例 INDEX 6 行（A-001..A-006）；蛋白质 × 成员不同出 |

| 18 | 产品台账「待完成」列＝产品\|类别\|日期\|概述\|当前进度，日期列写「开工 YYYY-MM-DD」；「早期设想」两列（标题\|描述） | 状态页产品视图直接读它渲染 |

| 20 | INDEX 可带标题与引用说明块（`#`/`>` 行），脚本只解析 `|` 开头行 | 说明块不影响解析 |
| 21 | **M5 指标口径分叉**：台账卡级裁定句式〔…〕的强认可**不被 M5 指标 2 计入**（M5 行级口径 vs 抽样器卡级口径）——卡级句式在备注列，M5 只看裁定列 | 移植时统一口径（M5 结算是否并入卡级强认可？）或至少在结算报告标注口径差异（已落地：报告末尾口径分叉提示行，不改统计行为） |

## 五、设计笔记要点

1. **最大风险：会话边界语义漂移**。Claude 会话短、起止清晰，「会话开始闪电 / 会话结束沉淀」有天然挂点；DSH 会话长命、可续接、可派生子代理共享工作区——触发点必须重定义（建议：以任务生命周期或用户显式指令为"会话"边界；派生子代理默认不执行闪电与登记，避免同一话题双重登记台账）。→ 已落地为 T1-T6（见 spec/lightning-trigger.md）。
2. **多议题窗口（公交车）**：单会话多轮天然覆盖多议题，「闪电跟议题走」规则文本保留，议题切换靠模型自判，无机制兜底；防重判据（议题键规范化、抽样前查一次/登记前再查一次）已落 SKILL 正文。
3. **裁定交互形态**：交互确认工具能力足够且更结构化（多题一次调用、逐卡裁定天然支持），但取消语义是异常而非空答，skill 文案必须覆盖（已落：取消/中断 → 「待补」）。
4. **定时任务可实现性**：定时机制为会话内提醒，跨进程重启存活与自动开跑新会话待确认；若不行，潮汐只能降级为"用户手动说跑潮汐"或操作系统级定时任务 + CLI。
5. **中文路径/编码坑（Windows）**：① 读文件编码三脚本不一致（BOM 错位风险）；② 生成器注入 now 时间戳 + 硬编码里程碑日期与规范漂移；③ 控制台 GBK 下中文输出风险；④ 路径含空格+中文，命令行调用一律双引号。
6. **打包结构建议**：夹具即 workspace（合成汤根含 `_氨基酸库/` 与若干对话文件夹，路径含空格中文压测引号/编码）；skill 文件项目级安放（`.agents/skills/`，随夹具走不污染全局）；状态页第一阶段不做 GUI 集成（落盘静态 HTML + 回复可点击路径）。
7. **泛化原则**：参数化"制度参数"（权重常量、台账句式正则、范围守卫判定文件名、卡字段节名）；保留机制本体硬编码（权重合成公式结构、呈现闸门四条增量判据、静默可审计、双向回写只追加、Resolver 三级匹配）。专属 vs 通用边界：隐喻词表（氨基酸/闪电/蛋白质/潮汐）、`@` 受控词表 v0、M3-M5 里程碑与哨兵阈值为原始汤专属；"结论卡 + 加权随机抽样 + 增量闸门 + 裁定回写权重 + 只追加台账"闭环为通用引擎，泛化命名留作二期。
