# 闪电触发点设计（T1-T6）

> 用途：原始汤联想机制中「会话开始闪电 / 会话结束沉淀」触发点的设计文档。
> 背景：经典挂点＝会话短起止（开始=第一个实质问题，结束=收工信号）。宿主环境会话长命、可续接、可派生子代理共享工作区——原挂点语义漂移，本方案重定义。
> 依据：机制规范（spec/SOUP-MECHANISM.md）一/二节、会话边界语义漂移风险分析、宿主能力实证（交互确认工具对宿主托管的子代理拒绝提问、取消/中断语义；任务生命周期工具的完成回调与暂停后恢复语义；定时机制为会话内提醒、跨重启不自动开跑；技能发现机制只渲染名称与描述——无自动触发钩子，一切靠模型逐轮自判，下列条款须以正文规则形式进入机制规范）。

## 一、推荐方案（规则条款，可直接并入机制规范）

**T1 闪电触发（会话级，唯一执行者）**：仅主代理会话（顶层代理）执行闪电与台账登记；派生子代理一律豁免——机制佐证：交互确认工具对宿主托管的子代理直接拒绝，裁定选择题本就发不出；且子代理共享工作区、继承同一议题，重复抽取会污染台账权重与 M5 统计。子代理须在最终报告里写"本议题是否属原始汤、建议主题关键词"，父代理统一判定、统一登记；多子代理并行同议题时只登记一次。

**T2 闪电时机（首问+防重双条件）**：范围守卫通过（根目录存在 `_氨基酸库/INDEX.md`）且用户提出本议题第一个实质问题后执行；执行前按第三节判据查台账，本议题已抽过则不重抽（除非用户明示"再抽一次/换一批"，登记时备注注明用户要求重抽）。

**T3 议题键与多议题窗口（公交车规则保留）**：议题键＝台账「会话」列文本（未建文件夹写主题关键词，归档回填文件夹名）。同一窗口明确切换大议题时新议题可再抽一次，独立登记；闪电跟议题走，不跟窗口走；每议题每会话至多一行。呈现闸门与静默规则不变。

**T4 沉淀触发（三信号）**：①用户说"收工/沉淀/存卡/记下来"；②讨论明显收尾或产出文件已写入对话文件夹；③任务收尾提议沉淀（只提议不自动执行，见第四节）。多议题窗口归档扇出（每议题独立文件夹+卡+INDEX 行），台账「会话」列按议题回填。

**T5 裁定回填（交互确认工具异常语义）**：呈现过碰撞且未裁定 → 用交互确认工具打包裁定题（一题一卡，稳定题号，四档强认可/认可/无感/反对，推荐项排首位）；工具被取消/中断 → 回填「待补」；跳过/未答同「待补」，潮汐清欠。拆分裁定落〔卡级裁定：卡全名=档；…〕规范句式。

**T6 幂等与中断**：登记台账是幂等锚点（先碰撞后登记，登记即"本议题已抽"）；异常中断未登记＝未发生，下次照抽；已抽样未登记的中断残留，续接后首轮只补登记不重抽。被静默的抽取也必须登记（沉默可审计）。续接（含任务暂停后恢复）不视为新会话：从上次登记点之后找新议题，没有则不触发。

## 二、备选方案（一句取舍）

- **定时机制"末班车"提醒**：到点检查未登记/未沉淀议题——判定从语义事件改为时钟，简单可兜底，但它是会话内提醒、无人值守不会自动开轮，且空转提醒打扰用户；只作 T2/T4 的兜底，不主推。
- **任务创建时自动闪电**：自动化最强，但任务粒度与议题粒度不齐（一任务跨多议题），易多抽漏抽；任务仅作 T4③ 沉淀提议挂点。

## 三、防双重登记判据（实施细则）

追加台账行前必须查重：筛选「日期」=今日 且「会话」列与当前议题键相等的行（议题键规范化：去「会话：」类前缀、去空白、全小写、主题关键词取前 12 字；已回填的文件夹名按完全匹配）。命中且「抽中氨基酸」列非"未执行随机抽样" → 本议题已抽过：跳过抽样，复用该行碰撞结论与呈现判定。归属判定只认「会话」列字符串（与 M3 抽样器文件夹名匹配约定一致），禁止用日期+备注推断。模型纪律：抽样前查一次、登记前再查一次。

## 四、任务生命周期挂点

任务收尾是高价值沉淀信号（长程研究型任务完成≈议题收尾）：任务收尾回调成功后同轮用交互确认工具出一题（题号如 `soup-settle-<任务标识>`，选项：立即沉淀(推荐)/稍后手动/本议题不沉淀），选"立即沉淀"才走归档；工具被取消视同"稍后"，不重问。任务受阻（blocked）不触发沉淀，但可提议把阻塞原因写进该议题卡的"未解问题"。任务创建/暂停/恢复均不触发闪电。

## 五、边界清单

| 情形 | 闪电 | 沉淀 |
|---|---|---|
| 寒暄/打招呼 | 豁免（等第一个实质问题） | 豁免 |
| 纯指令会话（"打开文件X"类） | 豁免（无碰撞价值） | 豁免 |
| 多议题切换 | 触发（T3），每议题独立登记、受防重判据约束 | 各议题独立扇出 |
| 异常中断后续接 | 不重抽；中断残留只补登记（T6） | 用户给收尾信号时正常走 |
| 子代理处理议题 | 豁免（T1），报告上交父代理 | 豁免，父代理统一归档 |
| 续接同一议题 | 不重抽（T2 防重） | 正常信号驱动 |
| 用户明示"再抽一次" | 触发并登记，备注注明 | — |
| 定时机制触发的轮 | 豁免 | 仅兜底检查、只报告不自动建档 |
| 任务完成 | 不触发 | 提议（T4③），用户拍板 |

## 六、待确认项

- 宿主无"会话级状态变量"供代理维护议题键——退化方案：议题键＝当次对话首个实质问题的主题关键词，与台账「会话」列一致即可（当前方案即按此设计）。
- 技能发现机制不渲染辅助元数据（如 whenToUse），模型路由只靠名称与描述——触发条款必须以正文规则形式存在，不能依赖元数据字段。
- 定时机制跨重启自动开跑（潮汐定时）不可行已实证（会话内提醒）；潮汐需操作系统级定时任务+命令行兜底，与本文件触发点无关。
